Specular

A lint check for design.

Most companies build one design system and end up with five products that don't look like they belong to it. Specular measures that gap directly — not from screenshots, but from what the browser actually rendered.

See the reports View on GitHub

What it does

A design system publishes a spec: a fixed palette of colors, a spacing scale, a type scale, a small set of approved fonts. Over time, real products drift from it — a marketing page ships an off-brand red, a legacy screen never got the new font, a component reaches for a spacing value that isn't actually on the scale. Nobody notices because nobody's checking every pixel by hand, and the drift is usually too subtle to catch by eye anyway.

Specular checks by machine instead. It headlessly loads a real page, reads the browser's own getComputedStyle() for every visible element — the literal value used to paint the pixel, after CSS cascade, theming, and runtime JS have all resolved — and compares it against the company's own published design tokens. The output is a single 0–100 deviation score per product, plus the specific elements and properties responsible for it.

How it measures

Four checks, run independently and rolled up together — no single property type can drown out another.

01 · color

Delta-E distance

CIEDE2000 distance in Lab space against the spec's palette. Alpha- and theme-variant aware, so a translucent or dark-mode variant of a real token doesn't score as unrelated drift.

02 · scale

Spacing, radius, type size

Distance to the nearest value actually defined on the spec's scale — not "is this a round number," but "is this a number this design system uses."

03 · type

Font family & weight

Categorical match on the resolved font stack, with weight checked as a secondary numeric signal.

04 · access

WCAG contrast

A separate, parallel category — not folded into the score above. Every sampled text element gets its real effective background resolved and checked against WCAG 2.1 AA/AAA. On-spec and accessible are different questions; a page can pass one and fail the other.

Try it yourself

Specular ships as a CLI. Point it at any live URL and it'll extract, score, and write out a report — no design-token spec required to just look at what gets sampled.

npx tsx src/audit.ts --url=https://example.com

Full setup, the token-adapter pattern for adding a new company, and the underlying design rationale are in the GitHub repository.
